# Phase 7 WP3 — Stock, Full, adjustments and late operations

16 November 2026. Implements the accepted plan's WP3; [WP2 acceptance](../acceptance/2026-11-16-phase-07-wp2-owner-acceptance.md). Native verification remains open.

## Ownership and scope

`ControlService`, `ControlRepository` and `ControlQuery` own one lifecycle for CASH/STOCK/FULL. Existing Cash classes remain stable wrappers with CASH defaults and the old Cash request shape. `ScopeControlController` binds STOCK/FULL in route definitions; body-selected scope, cutoff, expected values and predecessors are rejected. Inventory owns `ReconciliationAdjustmentService`, not a reconciliation balance writer.

All mutation authority is rechecked by CommercialAccess under Tenant → Shop → active membership roots. Roots serialize same-Shop starts and writers, including an empty active-session range. Domain source/control/Product/count/position locks and Audit occur before the generation lock; publication/commit follows it. Disjoint CASH and STOCK lifecycles may coexist, FULL overlaps both. Transaction effects determine writer blocking; credit/Transfer Sales still affect Stock. Effect-free drafts/master edits remain allowed where existing read restrictions permit them. Saved source-command recovery retains existing replay behavior.

## Frozen Stock evidence and exact observations

Freeze every current same-Shop Stock position, including inactive Products, zero/negative expected quantities and retained/unestablished cost states. New Products/positions after the cutoff do not enter the old dataset. First Stock period starts at Shop.created_at; later periods start at the latest finalized STOCK/FULL cutoff. Cash predecessor remains independently the latest finalized Cash-containing control, including Opening. FULL has both predecessor IDs/period starts and one new cutoff/watermark.

Approved count rows hold exact expected quantity and average cost. One immutable typed `reconciliation.stock_expected` Audit per Product, causally linked to the start Audit, freezes Product UUID/name/unit, cost state and position version. Start count/digest binds complete membership and all frozen fields, avoiding an unbounded Audit array or extra schema. Reads/commands verify count rows against that evidence. Device membership similarly remains per-Device causal Audit with count/digest; root scope/cutoff/generation are validated.

Physical quantities are nonnegative exact DECIMAL(19,4) strings, with explicit zero distinct from null; expected values may be negative. `StockCountAmount` uses digit-string arithmetic and rejects range overflow. Actual minus expected is signed variance; no JavaScript float calculates authoritative values. Draft actual/variance can exist server-side but expected/cost/variance never enter blind DTOs.

Stock saves/explanations require Product UUID and expected_updated_at. Commit requires expected_commit_revision: an opaque hash of all saved actuals/revisions plus optional Cash actual/revision. It contains no expected information. Every frozen line must be explicitly counted; a genuine empty Stock set is explicitly confirmed. FULL commits Cash and every Stock row atomically. Counts become immutable. Review and finalization require current grants, complete immutable Device decisions and matching generation. Nonzero variances need saved explanations. Finalization inserts exactly-one-source normalized Cash/Stock variance rows atomically, freezes context, advances both applicable chains and creates no operational movement. Abort retains evidence and never advances either chain.

Observer roles record the users who saved physical observations, separately from the committer. ON_DUTY known windows, COUNTER, REVIEWER and FINALIZER stay historical context rather than blame. Later notes are append-only, typed, max 2,000 characters; STOCK/FULL specify variance_public_id belonging to this control, including Full's Cash variance. Audit stores the note identity/type, not its full text.

Active count blindness applies across sessions/source APIs, prior control details, notes and late-event lists for responsible counters/Owners/starters. Read DTOs explicitly allowlist fields. Product identification/unit, actual/revision and aggregate counted/total progress are safe. Expected/cost/state/variance/explanations and adjustment links require committed counts and current review permission with no relevant blind count.

History, counts, readiness, Staff, notes and late associations are paginated (default20/max50); Product search max100 characters. Whole frozen-set consistency verification and commit necessarily inspect all frozen rows, so bounded response size is not a constant-cost claim. Menu offers separate keyed Cash, Stock and Full workspaces using the shared component. Predecessor links route by predecessor scope. Stock drafts survive page/search refresh, source conflicts and other Product saves; explicit use-saved drops a local draft. Full's unsaved Cash input survives Stock saves. Commitment is disabled while local Stock drafts remain. Saved progress comes from server acknowledgements.

## Reviewed one-effect Stock alignment

Only finalized nonzero STOCK variance belonging to the latest finalized STOCK/FULL control is eligible for a new adjustment. Active STOCK/FULL blocks it. Required grants: reconciliation.view/review/adjust, current FULL mutation access. Source variance/count/product/control and same-Shop linkage are verified; foreign, Cash, draft, zero, superseded and duplicate sources fail closed.

Preview uses permanent movement_public_id, variance_public_id and required reason (max500). It returns frozen expected/actual/delta, current quantity/cost/state, after quantity and SHA-256 review fingerprint bound to the normalized command/current position version/last movement. Post rechecks everything under locks; a changed position requires a fresh preview. Apply frozen signed variance ONCE to CURRENT position, preserving every later movement. F3: frozen51, actual48, delta−3; later Sale−2 gives49; adjustment−3 gives46, never48. Current average cost stays unchanged; existing non-acquisition state rules apply (VALID at nonpositive becomes RETAINED; RETAINED/UNESTABLISHED stay so). Position version/pointer update atomically with immutable RECONCILIATION_ADJUSTMENT/RECON_VARIANCE movement, reason, scoped variance link, Audit and publication. Original count/variance/control are never rewritten.

Tenant/Shop roots plus locked variance/position serialize competing adjustments. Existing same movement UUID with exact control/variance/reason recovers before today's eligibility checks, even after a newer control; changed details conflict. A different UUID cannot apply a second delta. Completion is derived from linked movements; no extra status/balance table. Generic manual correction/reversal cannot reverse this source or circumvent the one-effect policy. Any future exception needs a new owning contract.

## Late source acceptance and publication

Before acquiring the publication generation lock, ChangeSequenceService inspects newly published Stock movements, posted Sales with actual Cash payment, Cash Debt payments and Cash Financial Movements. Pure Transfer and effect-free/unposted sources are ignored. A source with occurred_at ≤ finalized cutoff < posted_at is linked to the newest finalized affected-scope control before posting. This is evidence of an operation arriving after the latest known physical boundary, not retrospective period reallocation to every older boundary. Exact-cutoff occurrence qualifies. Full can receive separate CASH and STOCK associations for one commercial operation's independently owned sources.

One deduplicated SYSTEM Audit association per control/source-kind/UUID/affected-scope preserves original occurrence and posting times. It never changes the source, old cutoff, counts, variance or baseline. New source effects remain in their posted_at operational period; old snapshots are never recalculated. The association and a reconciliation_session refresh publication commit in the source transaction before generation publication; source/Audit/publication failure rolls back together. No manual association write API or duplicate compensation is provided. Current source APIs/permissions remain owners of details; the late list exposes only source references/scope/times, not raw Audit metadata.

## API additions and recovery

Roots `/api/v1/shop/stock-controls` and `/api/v1/shop/full-controls`: GET list/members, POST start; `/{id}` GET detail; GET readiness/challenge/counts/staff/notes/late-operations/source-status; POST count/commit/review/explain/finalize/abort/acknowledge/exclude/note. Shared action bodies retain Cash conventions except Stock count/explain include Product UUID, STOCK/FULL commit uses expected_commit_revision, STOCK/FULL notes require variance_public_id.

`/{id}/adjustment-preview` POST accepts movement_public_id/variance_public_id/reason; `/{id}/adjust` adds review_fingerprint. `/{id}/adjustment-status?public_id=...` GET returns only found/movement identity/variance/time and inconclusive-absence guidance, with review+adjust authority. Cash adds GET `/{id}/late-operations`; old endpoints remain compatible. Same-origin authentication/CSRF/access/host checks and shared sensitive rate limit cover all roots.

No reconnect POST or offline queue. Control/note/adjustment recovery markers contain IDs/action only, not amounts, reason, note text, credentials or receipts. Cash retains its pre-WP3 marker key. Unknown adjustment retains original movement+variance IDs, blocks unrelated work/navigation and uses explicit status read. Found source linkage recovers; absent/404 is inconclusive. Explicit same-ID preview/retry requires re-entering original reason after reload. Never issue a new identity to dismiss uncertainty. Saved evidence requires online access; unsaved text is not durable offline.
